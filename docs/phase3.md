# Phase 3 — The Intelligence Layer: Triage, Categorisation, Dedup

**Goal:** raw submissions become clean, deduplicated, categorised challenges — with a machine decision that is always confident, abstaining, or reversible, and always explainable.

**The decision that carries the whole project:** the triage gate separating *grievances* (an official must act) from *challenges* (an artifact must be produced). Without it, the HEI dashboard fills with maintenance tickets and universities disengage within a month. This gate is not in the problem statement — it is your contribution.

## Work breakdown

### 3.1 `ai` — the single gateway
No other module talks to the LLM. Ever.

- OpenAI-compatible client pointed at OpenRouter for completions.
- **Embeddings in-house** via `@xenova/transformers`, loaded once at worker boot. Never in the API process — inference blocks the event loop.
- `embed()` and `complete()` as **separate provider slots**, so swapping either doesn't touch `dedup` or `matching`.
- Prompts live in `prompts/`, versioned, never inline strings.
- **Every call logged to `ai_calls`:** prompt version, model, tokens, latency, raw output. Every AI decision here is challengeable by a citizen or an institution — keep the receipt.
- Structured outputs schema-validated. A parse failure is a queue-for-human event, not a retry loop.
- Graceful degradation: LLM unavailable → work queues for human review, request still succeeds.
- Response cache in Redis.

### 3.2 `dedup`
Near-duplicate detection with a spatiotemporal constraint.

- Candidate generation first: **geo radius + time window as hard filters** (`DEDUP_RADIUS_METERS`, `DEDUP_TIME_WINDOW_DAYS`). Text similarity alone will not work — in comparable duplicate-report research most top-10 similarity scores fall below 0.5.
- Embedding stored with `EMBEDDING_MODEL_VERSION`; a model change is a migration, not a silent drift.
- Atlas Vector Search index over the filtered candidate set.
- Above threshold → attach to cluster. Borderline → human confirm. Below → new cluster.
- `dedup_decisions` records every call including the rejected ones — that's training signal later.

**Build the duplicate count as a first-class field.** Twelve people reporting the same borewell failure is a severity signal that feeds prioritisation, not noise to be discarded.

### 3.3 `classification`
Two LLM-assisted jobs, both returning a confidence.

**Triage** — grievance vs innovation-challenge. Below `TRIAGE_CONFIDENCE_THRESHOLD` → human review queue. Grievance-classified items go to `integrations` for forwarding, and **the citizen is told where it went** — never silently dropped.

**Categorisation** — hierarchical **multi-label** over the taxonomy. The domains are not mutually exclusive; a school-water-sanitation problem is three domains. Below `CATEGORY_CONFIDENCE_THRESHOLD` → human review.

**Abstention is a first-class outcome, not a failure.** Realistic accuracy for this class of task sits around 85–90%; treat that as the ceiling. A misrouted challenge sitting with an unqualified institution for two months is worse than a queued one.

### 3.4 `clusters`
- One cluster = one group of deduplicated submissions = at most one challenge.
- Holds duplicate count, geographic spread, first/latest report time.
- Cluster summary generated by LLM from member submissions.
- **Status propagates downward:** every duplicate reporter sees the parent's status on their own tracking ID. That's what makes 200 people feel heard by one project.

### 3.5 Review queue frontend
- Triage queue: one card per item, model's call plus confidence plus the reasoning, accept / override / send back.
- **Override is one click and always available**, and the override itself is an event.
- Duplicate merger: side-by-side comparison, map of the cluster, merge or split.
- `ConfidenceChip` with a "why" popover showing the model, prompt version and rationale — reused everywhere AI touches the UI.

## Definition of done

- [ ] A grievance-type submission ("handpump broken") is triaged out and the citizen is told where it went
- [ ] A challenge-type submission is categorised with two or three domains and a confidence
- [ ] Low-confidence items land in the review queue instead of being guessed
- [ ] Three near-identical reports from the same block within a week form one cluster
- [ ] A near-identical report from a different district does **not** merge
- [ ] Every AI decision shows model, prompt version and rationale in the UI
- [ ] A human override is recorded as an event and changes the outcome
- [ ] Pulling the OpenRouter key degrades to the review queue rather than erroring

## Demo line

"The model decides, but it also declares how sure it is — and when it isn't sure, a human decides. Either way you can see exactly why."

## Metric to actually measure

**The triage ratio.** Of real submissions, how many are researchable challenges vs grievances? This number determines whether the platform concept is viable, and no one else in the room will have it. Label a few hundred submissions by hand and report it.

## Explicitly out of scope

Routing to institutions, capability profiles, workflow states. Categorised challenges sit in a pool waiting for phase 4.

## Risks

| Risk | Mitigation |
|---|---|
| Embedding model weak on Indic text | `language` normalises to canonical language first; measure against a multilingual checkpoint before committing |
| Dedup threshold too aggressive, merges distinct problems | Start conservative, prefer false negatives, expose the split action |
| Worker OOM from the loaded model | Give the worker its own service, ~500MB headroom, batch embeddings |
| Prompt drift makes old decisions unexplainable | Prompt version stamped on every `ai_calls` record |
| Team inlines a second LLM call outside the `ai` module | Lint rule / review block. The audit story depends on the gateway being the only door |
